# 简历Mapping

用户只需提供**一批原始简历**和**一个目标简历格式**，可以是附件、多个文件或可访问的文件夹。目标可以为空白模板，也可以是指定的已填样例。缺哪项才询问哪项；两项已明确就执行。映射、数据整理、来源定位和核验记录由 Agent 内部完成，不要求用户准备 JSON、安装开发环境或配置字段。

## 先使用当前宿主已有的能力

优先级为：**当前客户端提供的文档/表格/PDF/预览工具 → 已加载的相关文档 Skill 和宿主随附运行环境 → 本机已可用的工具与本包可选脚本**。以实际工具调用确认能力，不因知道一个工具名就认定它可用。根据实际来源和目标检查需要的能力，不先要求整套软件齐备。

- 安装本 Skill 与准备业务资料分开。安装时优先宿主原生导入或现有文件工具复制目录并验证加载；见 [INSTALL.md](INSTALL.md)。不把 Python 自测设为所有宿主安装成功的条件。
- 大模型负责理解原文、判断记录边界、识别目标字段、处理有依据的映射和回查。文件读写、表格保真、日期计算、数量/文本校验等确定性操作优先交给已有工具；不要靠模型重抄长文本。
- 有可用原生工具时不强制绕回整条固定 Python 管线；可以单独复用已经验证过的计算、证据和规则校验，不为选择原生路径重写冲突的近似规则。宿主附带 Python/Node 等可以直接复用，但不要求用户另行安装 Python、Office、LibreOffice、OCR 套件或几百 MB 的运行包，不自动进行全局或私有环境安装。
- 只发现现有能力，不自动安装其它 Skill、插件或上传业务原件到新服务。当前客户端已有且用户授权的文件处理环境可以使用；跨入新的第三方服务须遵守本次授权。
- 某个必需能力确实缺失时，先完成其它可做部分，再准确说明所缺功能和对本次交付的影响。不把读取失败当资料为空，不偷偷换目标格式，不在无法实际看图时声称排版通过。

原生/宿主工具路径按 [references/host-workflow.md](references/host-workflow.md) 执行。仅在选用现有脚本时阅读 [references/scripted-workflow.md](references/scripted-workflow.md) 和所需格式参考；不把其专有 JSON、审计文件和命令门禁强加给原生工具路径。

## 信息与规则

目标是在现有资料条件下，尽可能把已有信息准确落到目标对应字段，不要求每个人所有字段非空。保留人物归属、每段教育/任职/项目边界、项目介绍、技术、职责和成果；一个文件可能多人，多份文件也可能同一人，不能只按文件名或同名合并。

- **日期**只对明确日期字段/日期片段按目标格式统一，保留原有年/月/日精度和“预计、在读、至今”等限定，不补造月份或日期；长描述不能因包含“现在”等词而整体被归成日期。数字经验未注明单位时保留原值与业务范围，不自动加“年”。无法解析、逆序或来源矛盾应回查并保留疑点，不猜改。
- **学历和学位**绑定同一条最近已毕业的教育记录；在读不参与摘要。来源明确学位优先，明示“无学位”时留空、不套默认；确实缺失时按用户规则本科默认学士、硕士研究生默认硕士、博士默认博士、大专学位留空。每个已毕业判断须有同条记录的实际毕业依据；本人已填写的毕业院校信息可与同校教育记录交叉绑定，通用表头本身不能证明毕业。没有足够依据时保留已知教育原文，不能用过去的结束日期或默认学位反证已毕业。
- **多段教育**在对应框内分行/分段，保持每段内容关联。来源只给专业或学历等部分信息时仍保留对应教育记录，学校/日期未知则留空；这不代表已确认毕业，摘要另按已毕业规则选择。所有项目按可确定的开始时间由近到远排序，日期精度交叠保持稳定，不确定开始时间的排后；客户、角色、介绍和职责整条跟随，不限制模板示例数量。
- **学历显示**统一只保留本科、大专、硕士研究生、博士等学历名称，去掉“统招、全日制、学信网可查”等附加描述，不再转放到补充区。“在读、未毕业、预计”等状态只在对应教育经历中保留。个人学历/学位摘要只取最近已毕业的同条记录：大专毕业、本科在读时填大专；本科毕业、硕士在读时填本科；无法确认任何已毕业记录时摘要留空，不能把在读学历写入个人学历。补充区不再重复列“最高学历/最高学位”自述，避免与已毕业摘要混淆。简化显示不改变学校、专业或学位及内部来源原文。
- **项目客户**优先取明确客户，空缺时回查该项目标题、介绍和职责；原文明确的完整服务对象优先于标题简称，保留同项目多家客户及分行/机构限定，不只取首个关键词或泛化母公司。不把雇主、实施方、合作方或产品厂商自动当客户，也不跨项目借客户。标题与正文主体冲突、无法确认客户时留空并保留冲突，不猜选母公司。
- **相关信息推导**必须有同一人物/记录的可靠依据，并保留直接原文、来源位置及推导理由。例如完整号码明确属于本人时，用已有工具验证身份证格式、出生日期及校验码，再推导登记性别；不按姓名、照片猜测，也不在输出中暴露无关完整号码。
- **岗位/年限/项目状态**保留语义范围；求职意向不能冒作现职，项目技术职能不能冒作整个任职的正式职务，提及协作团队或技术库不等于本人承担该角色。根据本人职责判断，例如“后端开发、配合前端联调”不能判成前端角色；明确的测试、需求分析、项目管理或技术架构职责不能用通用“开发”兜底，相关角色也可能写在“负责模块”等栏目中。个人参与结束不能自动代表整个项目完成。年龄/截至日期注明本次实际计算日期，不能沿用旧缓存的日期。
- **证书与培训**分别处理。培训/课程名称不能填成资质证书，放在教育或其它相关补充区保留原文；只有明确证书依据才填证书栏。证书取得、发证、到期及当前有效资格主张分开，历史附件不能自动证明当前有效。
- **OCR 按需**。文字已足够且无相关矛盾时，即使附有学位证/毕业证照片也不强制 OCR 或逐张审证。相关字段缺失、冲突或扫描正文确需识别时，用现有多模态看图或 OCR，保留归属和原图定位；识别不清不编造。除非用户另要求，不扩大到全部证件真伪和有效性审查。

## 来源到目标的完整核验

首次填写 → 检查实际目标空项 → 逐项回查当前来源 → 补回可填信息 → 重新检查内容和排版。不能只验证整理后的数据到文档，也不能把旧“未提供”标签代替本次核查。

内部证据可使用宿主文档位置、PDF 页码/文字或图像区域、Word 段落/表格、Excel 工作表/单元格及精确原文，不强制某种文件格式。直接提取、规则默认、来源推导、确实缺失和存在矛盾须能区分。长文本优先使用原文引用或现有工具精确复制，避免模型重写造成缩略或错字。

空项回查要区分：源未提供、信息不足/冲突、解析失败、依规则留空、已在合理位置显示、已有但漏填。可填项补到对应位置；其余正常留空，默认不在简历正文写“未提供/待核实”，也不要求用户逐项确认普通空白。相关原文有技术/角色等信息时继续回查语义，不能只搜索同名栏目。

检查最终文件中的每人身份、记录数量、关键字段、全部长描述、目标对应位置和全部空项理由；确认无串人、跨项目串填、截断和样例事实残留。原生路径与脚本路径采用同样质量标准，不能因工具路线改变降低完整度。

## 模板、排版与交付

本次用户目标是设计依据，保留字体、字号、边框、列宽、页面设置、页眉页脚和标签。已填样例只取格式并清空样例事实，模板标志/图片槽位按实际用途处理；原件只读，输出写新路径。复杂对象不支持时另做本次适配并核对，不默认转换成另一种文件格式。

先实际查看最长与最短样本，再批量生成。长内容通过动态续行和自然跨页保留，不能删除经历、截断描述或过度缩小字号。用当前宿主预览/渲染工具打开最终文件并实际查看全部页图，检查遮挡、溢出、乱码、跨页边框、空白页和孤立标题；文本检查不能替代看图。旧页面仅在此前已实际审查通过、无待修问题且像素哈希完全相同时复用；已知问题页剔除出复用集合，修复后的变更页面全部重看。

优先使用宿主缓存和已审事实，但要验证当前原件/模板及引用仍有效；新目标重新检查字段和空项。复用过程如实记录，不能把已看过样本的回归冒称首次无参考提取，也不能把当前宿主通过扩大为所有客户端/系统通过。

只交付需要的目标文件和简短结果。普通缺失不代表转换失败，来源矛盾仍单列保留，不虚构确认。最终说明实际用到的宿主能力、是否新增安装、内容/排版完成情况及确实影响使用的限制。真实简历、客户模板、缓存、核验和输出不进入公共 Skill 或安装包。
