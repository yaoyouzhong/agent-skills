# 可选脚本工作流

仅当当前宿主已有可用解释器和所需库，且使用这些工具能保留或提高质量时读取本文件。这里的 JSON、脚本名、参数和回执是这一实现的契约，不是其它客户端的必装依赖或统一 API。宿主原生文档路径见 [host-workflow.md](host-workflow.md)。用户无需额外安装 Python、Office 或大型运行包。

## 输入和工具

用 `scripts/extract_sources.py` 统一提取 PDF、DOCX、XLSX/XLSM、CSV/TSV、TXT；旧 DOC、RTF、XLS 使用已有 Office 或 LibreOffice 转换任务副本。先找当前宿主提供或本机已有的 Python；有依赖查询工具才使用它，没有也可通过通用环境检查继续。`environment_check.py` 只读检查依赖、平台和渲染能力，不启动应用、不安装软件。旧格式被 Office 阻止时保留具体错误，不自动修改信任中心。详细命令见 [references/workflow.md](workflow.md)。

PDF 保存逐页文字和坐标；Word 保留正文、表格、页眉页脚位置；Excel 保留工作表、单元格、合并区域、原值/数字格式、公式和缓存。隐藏工作表与隐藏行也需要核对。扫描页、图片、文本框、未缓存公式、损坏/加密文件会产生复核项，不能当作空简历。OCR 或视觉识别后保留原始提取与识别依据，不向第三方上传原件，除非已有授权。

## 整理与字段规则

阅读提取内容，结合原件处理多栏顺序、跨页断行、表格合并和人物边界。一个文件可能包含多人，多份文件也可能属于同一人；按身份和履历核对，不能只按文件数或姓名合并。内容冲突以可核对的正文证据优先于文件名，无法消解的记录为待核实。

按 [references/data-and-template.md](data-and-template.md) 写任务内的结构化 JSON。保存每个人的来源 ID，重要字段的页码/段落/工作表单元格和原文摘录。保留教育、任职、技能、全部项目、个人作品、技术、职责和成果；不为适应模板省略长文本或只保留前三个项目。

项目经历默认按开始时间由近到远显示，编号同步重排，整条项目及其客户、技术、职责、介绍共同移动。先满足日期可确定的先后关系，其余候选按来源原序优先；不为年份或月份不全的日期补造精度。开始时间缺失或无效的放在后面并保持原顺序。显示排序不改变结构化原始索引及来源证据；用户明确指定另一顺序时在重复映射中设置 `order: source` 等任务内顺序。多段教育经历按实际数量全部保留，不能只保留摘要所选的一段。

多段教育在同一表格框内时，每段独立一行或一段，按模板字段顺序呈现时间、学校、专业、学历与学位；继承目标字体、字号、行距和边框，长内容自然换行。Word 单格重复区可用 `combine_records: true`。在读状态明示，缺失项留空；摘要仍取最近已毕业记录。

多人资料同时核对名册、标题和详细履历，同一人的岗位、年限或学历可能分散在不同表格。可用 `person_source_scope` 明确该人在各来源中的原文单元范围，包含已核对的名册行与正文；不能只取详细表而漏掉名册，也不能借用其他人的同值单元。图片同名人员须绑定 `owner_person_id`，已有其它身份信息可用 `identity_checks` 交叉核对。

在数据顶层明确 `processing_date`（本次处理日期，YYYY-MM-DD）。用 `form_grid.py` 复用标签别名、合并单元格邻接及真实表头定位，具体字段配置仍放在任务内；不要假定表头一定紧接章节名。多人 Word 行表按实际行限定项目、教育与任职证据，非行表须复核范围，不能让最后项目延伸到下一人的履历。

用户确定的默认规则由 `scripts/apply_policies.py` 执行并写审计记录：

- **学历、学位均取最近已毕业的教育记录**。按毕业时间判断“最近”，不能简单取最高学历。明确在读、肄业、未毕业记录不参与；毕业状态未知时先核实，不能把日期已过等同于毕业。
- 该已毕业记录学位为空时：本科填“学士”，硕士研究生填“硕士”，博士研究生填“博士”；大专学位留空。已有明确学位优先保留，大专出现异常学位时单列复核。未知学历不猜测学位。不要套用到在读记录。
- 任职/项目的客户名称为空时，从**对应项目名称、项目介绍或实施内容**尽量提取。原文简称保持原样。先判断实际客户，再记录证据；不能把任职单位、产品名称、技术厂商或行业泛称自动当客户。
- 客户补全建议由 Agent 阅读后给出，脚本验证客户文字和证据确实出自对应记录；没有确定依据就留空，内部记录原因，不因普通缺失要求用户确认。来源实际存在歧义时再提示。不要跨项目串填客户。
- 毕业院校、专业等与学历一起呈现的摘要字段须绑定同一选中教育记录，不能固定取 `education[0]`。职位、职称、职务、响应单位年限与现职年限按本次模板各自语义取证；文件名级别、银行经验、样例单位或过去项目结束日期不能自动替代这些不同事实。项目独立角色栏须单独回查同项目职责和标题，旧模板合并显示过不能代替本栏填写。
- 仅由某些项目归纳的技术职能，不直接写成整个雇主任职期间的正式职务。原任职岗位缺失时，可在该段补充“项目技术职能”并限定对应项目或时期，岗位字段仍留空；确有同期岗位原文时，项目角色的推导须保留任职引文及时间包含关系。
- 来源仅给求职意向、期望或应聘职位时，映射到通用“职位”栏须保留这一限定，或放到相关补充区；不能省去限定后声称其为现任岗位或本次投标已分配角色。
- 日期只保留原文精度，不自动添加入学 9 月、毕业 7 月。未确定的电话、民族、证书、客户等不凭空补全。

在读记录保留在来源和结构化数据中以便追溯；是否在目标模板显示取决于本次要求，不能让其覆盖已毕业的学历与学位。审计信息保留在工作目录，不写进客户正式简历。

在默认规则前运行 `record_checks.py`，统一核对教育、任职、项目和摘要的有效日期、逆序、异常早期日期及未来经历。原始 Excel 日期即使目标留空也会列复核，不猜改 1905 等异常值。毕业状态必须有同一教育记录的明确毕业表述、明示毕业时间字段及其对应日期、同行原始授予学位、已看图片的证书摘录或真实用户确认；默认学位、普通结束日期和相邻教育的学位不能作为依据。证据绑定失效时撤回依赖该证据的默认值。日期精度重叠而无法确定最近毕业记录时保留待核。

## 原文完整度与事实来源

按 [references/quality-and-review.md](quality-and-review.md) 保存原文单元、项目边界、字段引用和类型化事实。先用 `record_evidence.py` 定位，再执行默认规则和 `field_facts.py`，最后用 `source_audit.py` 从原文反查字段完整度。候选差异需要逐条补回、确认等价或按有效授权排除；不能只验证 JSON 到 Word。

学位默认、原文推断、直接提取和未提供必须分开；未知毕业状态不能反向用默认学位证明已毕业。水印清除保留原文/清理文本/删除坐标，复核多栏、整页容器表格和隐藏 Excel 内容。缺客户要阅读对应记录并保留未知原因，不能为了非空率猜填。

**OCR 按需使用。** 文字资料已提供所需字段且没有未解决矛盾时，即使附有毕业证、学位证照片，也不必重复 OCR 或逐张核对附件。默认 `media_policy: when_needed`；仅有附件提示不阻断验收，缺失/冲突的具体事实仍单独待核。只有用户另要求全面审证时才用 `review_all`。来源质量判断统一由 `source_quality.py` 执行，不把排版/下拉提示当成缺失业务字段。

需要识别时，`media_evidence.py --ocr` 保留原图，执行四方向、小角度纠偏和短文本重试；候选排名不是置信度，低质量结果须看图。直接看图足够时可跳过 OCR。实际看图后才用 `attach_reviewed` 接入带人物、图片哈希和复核人信息的摘录。证书取得、发证和到期时间分开；`credentials` 可记录历史附件与当前资格主张，不能用过期附件证明当前有效。流程见质量参考。

允许有可靠依据的交叉推导，使用 `source_inferred` 并保留原文、归属和推导理由。例如性别未提供，但完整身份证号明确属于本人时，可用 `cross_fields.py` 检查号码格式、出生日期和校验码，再按顺序码推导登记性别；它不是证件真实性认证。明示性别冲突时保留原值并提示。姓名、照片或他人的号码不能作为猜测依据，完整号码只放本地必要证据，不在摘要中暴露。

日期可用 `normalize_dates.py` 统一成 `YYYY-MM-DD`、`YYYY-MM` 或 `YYYY`，至今类写法统一为“至今”，保留预计等限定语和原文精度。没有日就不补日，日期不明确或无效不猜改。原值保留在变更记录；格式等价的证明/快照随之更新，已失效的证明不会恢复。模板明确指定另一日期显示格式时遵从该模板。

Excel 日期样式读成 `#VALUE!` 时须查看保留的 XML `raw_value`；`source_audit.units_for` 会将数值原编码作为独立 `excel_raw_cell` 单元提供。原始错误值和告警保留。只有字段标签、相邻关系与日历校验足以证明编码含义时才解释（例如出生年月格的有效八位 `YYYYMMDD`），不能把任意数值猜成日期或凭错误值认定未提供。

## 目标模板与生成

先读取模板的字段、结构、重复区和真实排版，再决定映射。保留用户模板的字体、字号、颜色、边框、列宽、页面尺寸、页眉页脚和标签；不套本项目的固定行号、人数、项目数或网格宽度。

用户以已填简历指定格式时，只在任务副本中抽取选中人员的格式。`template_prepare.py` 按原件哈希、实际表格号和逐格期望值清除样例，拒绝残留样例；有图片的格式须另外明确图片槽位，不能误删模板标志。复制后验证 Office 正常打开。紧凑模板的长描述可接在项目续行；补充字段可用 `append_rows` 克隆现有宽行保留。具体见 [references/format-adapters.md](format-adapters.md)。

- **Word 模板**：`scripts/template_docx.py inspect` 查看真实单元格及段落；根据该模板写任务内的 `template-map.json`，再 `build`。支持多个正文表格、段落字段和任意数量的教育/任职/项目行块。行号和单元格号必须来自当前模板。DOC 模板先转换任务内副本。复杂嵌套表格、图片/关系复制或本脚本不能表达的布局，按实际模板另写任务内适配，不把不支持当已成功。
- **Excel 模板**：`template_xlsx.py` 使用来源门禁和任务映射，通用环境默认通过 openpyxl 写原生 XLSX；已有 Artifact Tool 的环境可显式选其后端。支持动态记录块、现有格式复制、合并区域、长字段续行和打印区域；每人独立工作簿。通用后端拒绝可能丢失的复杂原生对象，不把不支持当已成功。用 `render_output.py --xlsx ... --sheet ...` 在现有 Excel 或 LibreOffice 实际打印渲染。细节见格式适配参考；不支持的原生对象单独适配，不能悄悄换成 Word。

构建和检查均须传当前有效的 `--source-audit`；正式输出要求通过，明确来源冲突只允许按质量参考生成标明 candidate 的待核候选；数据、原件、提取或审计代码变化后重审。构建器会拒绝未映射的非空业务字段，防止模板变更导致静默丢内容。将内容映射到合理的现有位置；确需省略时必须有本次要求，并在映射的 `omit_fields` 记录具体理由。保留原件，所有输出写新路径。

## 核验与交付

先检查来源哈希、人物对应、字段完整、动态项目数量、每人输出内容及模板包保真。Word 使用 `template_docx.py check`；渲染使用 `render_output.py`（Windows 可用现有 Word 的隐藏独立 COM 实例；其它环境使用已配置 LibreOffice，可传 `--soffice` 或设置 `RESUME_SOFFICE`）。使用任务副本与隔离实例，不保存回原件，不接管用户已打开的 Office 实例。没有渲染器时不能声称最终排版已验收。

渲染后将完整页图与原模板对照，检查全部页面的截断、重叠、空白页、孤立标题、跨页边框和乱码。程序的文本覆盖检查不能替代视觉检查，生成 PDF 不能冒充已视觉验收。每人是否新起页、是否按组汇编以本次模板与用户要求为准，不能全局强加无分页控制/负缩进/填充补页等历史修复。

逐人渲染文字检查可用 `check_rendered.py`；全部页图实际复核后用 `review_ledger.py` 生成版本绑定回执。未审字段或未看页图只能标候选，不能复用旧报告宣称验收。新格式用独立真实样本测试，内置无隐私回归见 `tests/test_pipeline.py`。

区分“按现有资料完成转换”与“全部原始事实核实无疑”。正常缺失可由执行 Agent 阅读现有来源后标为 `not_provided`，无需另找用户确认。毕业状态等缺少依据时不据此生成默认学位或已毕业摘要，仍可保留已知教育原文并填写其它字段。技术回执的 `candidate/closed` 用于追踪事实和检查状态，不能直接作为转换成功人数或提取准确率；有待核事项时按脚本契约使用 `output_mode=candidate`，完成可确定内容的交付并说明局部限制，不虚构确认或绕过来源完整度检查。

`review_queue.py` 输出按人分组、附原文和定位的清单，并合并同一来源矛盾的关联提示。`review_actions.py` 可回读 JSON/CSV 复核意见，更新字段/证据后重跑全部事实和来源门禁；队列或原件变化、假引文、重复决策均拒绝。延期不等于确认。命令及决策格式见 [references/review-actions.md](review-actions.md)。回执包含逐人状态，已核清人员可独立确认。

`layout_review.py` 提示短尾页、页边界和孤立标题，提示仍需实际查看。增量复核仅复用旧回执中像素哈希完全相同且确实已看的页面，变更页全部重新看；事实和来源另行重跑。`evaluate_benchmark.py` 对独立人工标注评测，并保留首次预测、基准更正和调优后复测；只报告实际标注范围，不能把程序测试数当作真实准确率。

只交付用户需要的文件和简短结果，说明实际验证过的输入/目标类型和未解决项。不得把不同格式的“支持流程”都说成已在本次实测通过。不要将本项目人员资料、原始简历、审计缓存或生成文档打包进 Skill。
