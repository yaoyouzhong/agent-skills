# 使用当前宿主文档能力

这是默认路径。工具和客户端名称由当前会话决定，不维护三客户端白名单，也不把作者电脑的路径复制给同事。

## 发现能力并完成一个小样本

查看当前可调用工具、现有文档/PDF/表格 Skill 和宿主依赖查询工具。只查询本次输入输出需要的能力：读取来源、保留结构地编辑目标、保存文件、生成/查看页图。没有专用依赖查询工具时直接使用已有原生文档功能；不要先寻找或安装 Python。

可以用一个无隐私小样本确认读写和预览，再处理真实输入。文件保存后重新打开检查，宿主只显示“创建成功”或文件存在不能代替内容核验。原生导入后确认当前会话确实能加载本 Skill。

宿主随附的解释器、库和渲染器属于已有工具，允许直接调用；已有本机 Office 也可使用，但都不是要求用户提前安装的统一条件。本包脚本可辅助精确复制、确定性规则或独立检查，不必为了保持某条命令链而绕过更适合的宿主工具。没有解释器并不妨碍具备原生文档工具的宿主工作。

## 读取来源和识别目标

- PDF：读取全部页，复杂多栏、表格、扫描正文必要时看图确认阅读顺序、人物和项目边界。不能把工具返回的截断摘要当完整简历。
- Word：读取正文、相关表格/文本框、页眉页脚；已填格式样例明确选定哪一人，只复制格式。确认其它正文、图片和关系中没有残留样例事实。
- Excel：读取全部相关工作表、隐藏行/列/表、合并单元格、公式及缓存、日期原值和显示格式。异常值、缺失公式缓存等不是“未提供”；必要时用已有工具读取底层原值，并结合标签和日历校验判断，不能随意猜日期。
- 识别目标的实际字段、重复区、续行与打印范围。现有内容放在语义相关的字段或补充区；目标没有栏目时合理保留原文，不能塞入无关字段或静默删除。

集中阅读同一原文一次，建立内部人物与记录清单。每个输出字段保留足以回到原文的位置和摘录；结构可以用宿主自己的数据对象、表格或任务文件，不要求固定 JSON。跨文件合并先核对身份，项目字段始终绑定自身记录。

记录边界和字段按内容、版面及标签共同确认，不仅依赖固定行位或预期标题。有独立项目标题/日期的段落不能并入前一项目；技术栈后没有“职责”标签的叙述仍可能是职责。只有专业/学历的局部教育资料也应在教育区保留，不因缺学校或日期而丢掉整条。未要求去重时保留重复来源记录，可内部标记，不按同名静默合并。

横排的项目名称、角色和日期分别映射，不把相邻岗位串进项目名；“个人作品”等范围限定随对应记录保留。学历摘要和各段教育的学历只显示规范名称，去掉“全日制、统招、学信网可查”等附加描述；补充区不重复这些已删除描述，也不再另列“最高学历/最高学位”自述。“在读、未毕业、预计”等状态只在对应教育经历保留，个人摘要仅选择有实际毕业依据的最近记录；没有可确认的已毕业记录就留空，不把在读学历或其学校/专业/学位借入个人摘要。内部来源原文和毕业依据不因显示归一化改变。

## 完整度与剩余空项

先按当前资料填写，再按最终文件实际单元格/段落逐项检查。合并字段只计一个显示位置，可选续行未生成不算漏填。目标有明确对应字段且来源有依据时优先填入该位置，不能用补充区出现过原文代替字段映射；目标采用合并字段或没有独立栏时，记录已有信息的合理显示位置，不为提高非空比例重复拆填。

剩余每一空项均回查现有来源，记录原因、位置和本次判断。来源确实缺少时不造“缺失引文”；来源有冲突/无法解析时保留具体问题；可补时修复并重读最终文件。已知人物、教育/任职/项目数量和长文本覆盖要与来源清单对照，不能只比字段非空率。

空项所需信息可能在原文件的相关图片或嵌入附件中。按需检查附件关系和实际内容；Excel 的 OLE 包、附件图标或文件名不能代替里面的证书/PDF。用现有工具只读提取并查看相关材料，绑定本人和同条教育/证书记录，不运行附件程序或宏。若宿主无法读取，标为相关附件尚未核实，不能直接断言来源未提供。已足够填写且无矛盾的字段不触发整批附件审查或强制 OCR；历史证书事实也不能自动变成当前有效资格主张。

关键词/字典匹配只用于生成候选，不能把“未命中”批量写成“源未提供”。客户空项须实际阅读本项目标题、介绍和职责中的服务对象，角色须读本人负责的动作；明确非银行机构同样需要映射。未读过相关原文时不能声称已经逐项回查。

已明确服务对象但只提供匿名或部分机构称谓时，按原称保留，不补实名或母行。区分被改造的平台业务所属方与仅被使用的云、组件、接口等工具提供方；同项目明确自研归属时保留“自研”限定，不冒称外部合同客户。

非空字段也需检查语义和原文对应位置。项目介绍/职责原文有长段，但目标只出现日期、“至今”或其它短标签时，应回查表格合并区及前后标签，不能以非空判通过；同一人其它位置出现相同词也不能证明这个项目的字段正确。文字提取未读出的公司/教育等信息，如原页面可见，应用现有看图能力回查，不能归类为源未提供。

批量或复杂来源的初稿完成后，另做一次**从原件逐记录到实际目标字段**的核对，再回查目标空项；不能只拿初稿整理的数据验证它生成的文件。采用当前宿主已有的独立复核能力或同一 Agent 的第二次来源回读即可，不把多 Agent 当安装条件。发现的新问题按字段语义修复并重读实际输出，保留初稿和修复证据。

学历学位、客户提取、日期精度、排序和证据归属遵守 SKILL.md。优先用已有工具执行计算、校验身份证校验码、复制长文本和统计记录；需要脚本且宿主已有运行环境时可以按需调用本包脚本，字段含义仍由模型阅读原文确认。

日期归一化只用于日期字段，排序使用来源已有的完整年/月/日，不先截成月再比较。同项目客户可有多家和明确分行/部门，不以银行简称替代全部使用方。角色先区分本人动作、协作对象和技术名称；例如使用 UI 组件库不代表 UI 设计，与前端联调不代表本人做前端。学历完成依据与学位缺失/明示否定分别记录，空单元格不等于“无”。这些确定性或可核对规则有现成工具时直接复用，避免重新编写过宽的关键词判断。

项目角色同时回查职务、本人职责和“负责模块”等栏目，保留明确的测试、需求分析、项目经理、架构等信息；没有角色依据时留空，不因出现技术名称或“协助开发”就套用“开发”。目标角色不局限于前端/后端等固定标签，实施、数据清洗/迁移、维护或协助设计等有原文依据时也应填写，并保留“协助”等范围限定。原文已经明确本人前端、后端或管理组合时，独立角色栏保留该精度，不因正文仍在就泛化为“开发”。

## 渲染与最终交付

使用宿主已有预览/渲染能力导出目标文件的实际页面，先看最长/最短样本再全量。不能拿重新排版的 HTML 或另建 PDF 预览替代目标 Word/Excel 的实际渲染；截图需来自同一最终文件。

PDF 的版面软换行应在同一自然段内接回，保留真实条目和段落；不能把源表头、重复身份/教育资料整段搬入补充区代替字段映射。补充区保留目标没有栏目而确需保留的业务信息，避免重复挤占项目版面；整理后仍按原文忽略布局空白核对全文。

核对全部页面的文字、边框、续页、字体和留白。只有像素哈希与此前已实际审查通过且无待修问题的旧图完全相同，才可复用；已知问题页必须从复用集合剔除，当前变更页实际重看。文本和位置校验、视觉核验、来源事实判断分别记录；任一没有完成，如实标出该项，不以程序通过覆盖。

长客户名称仍放在客户栏，必要时只调整该内容格的段前后距与行距，保留原字号、列宽、边框和全部机构名称。末页孤行或短段被拆到下一页时，局部调整段落分页与间距并实际重看，不靠删字、缩小字号或移动到无关字段处理。

Word 表格内的短补充段还要检查表行拆页：段落的“段中不分页”可能仍被表格行拆分覆盖，必要时只对该短行使用“行不跨页”（`w:cantSplit`），并让小标题与正文同页（`keepNext`）。超过一页的长项目正文继续允许自然跨页，不能全局禁止拆行造成溢出。控制项写入成功不代表孤行已消失，须以最终实际页面确认。

记录本次实际用过的能力与验证：宿主原生工具、随附运行环境、本机已有组件、是否发生新增安装，以及最终来源/目标版本。仅报告实际测试范围，不承诺其它宿主具备同样工具。正常资料缺失允许留空，局部来源矛盾不阻止其它可确定内容交付。
